# TH10 PSP-1000 版（2026-10-03、正式版は 2026-10-05）

**正式版（2026-10-05）: 40（build_queue 42_rel40、sha 42ca6302、BUILD_ID th10-r39a-1000-stage4-20261004、XMB「TH10 PSP 1000」）を PSP-1000 の試験枠 TH10T に入れた。** 1 つ前の 39 は同じフォルダに EBOOT.PRE_8a2b4e40.PBP として残してある。40 = 39 ＋ TH10_FAST_RNG_UNIT（弾の一斉消去で SoftFloat が 1 tick 2,147 回走っていたのを、結果を変えずに直接計算）＋ TH10_RENDER_FAST_BULLETS ＋ TH10_RENDER_FAST_GE_STATE（VRAM 満杯で滝の描画ごとに確保失敗と全走査をしていたのを止める）。PPSSPP の 1000 設定で、実機で記録したリプレイの 4 面（3fc01d21）、rep3、4→5・5→6、1〜6 面が全部状態一致。実機の A/B は結果ファイルが取れず（--ticks の設定ミス）。事前に決めた基準（差がはっきりしなければ 40）で 40 を採用した。39 の実機プレイでは 6 面まで確保失敗 0（峰 18.01MiB）。

方針: 16bit テクスチャは 1000 だけ。1000 は録画に対応しない。ME の eDRAM 2MiB を RAM の代わりに使う。

## 分かったこと
- PSPSDK の `PSP_HEAP_SIZE_KB(-N)` は N を無視し、ヒープ＝MaxFree−512KiB。ヒープを増やすには他の消費（スタック等）を削る。
- ME の eDRAM の化けは、VME メモリモード 0xBCC00040=1（m-c/d の psp-media-engine-reload README の手順）が原因。MECC 既定の 2 なら化けない（1000 実機で確定）。
- PPSSPP の試験はトレースの文字列のぶん実機より厳しかった。

## 実機の結果（2026-10-03、39_1000g、実測 459MHz、デモ→1〜4 面、1021 秒）
- メモリ: room_start 21,245,951（PPSSPP 21,258,239 とほぼ同じ）、峰 17.35MiB（4 面の読み込み）、確保失敗 0。
- volatile: locked=1、使用 1.70MB（効果音が eDRAM へ移ったぶん PPSSPP より 1.87MB 少ない）。
- ME の音: me_jobs=59,536、model=0、mapper=3、witness 0x279c1d44、eDRAM 2MiB。途切れ 49・捨て 14（Go の 32_play と同じくらい: 815 秒で 40・22）。
- 効果音 eDRAM: 37 個・1,871,075B、932/992 ブロック、読み込み 67ms、照合 8,291 回で化け 0・無音化 0。
- 速さ: 1 秒あたりのゲーム処理回数（等速は 60）1 面 58.38・2 面 56.18・3 面 55.77・4 面 54.15。処理落ちの率は全体 2.10%、面別 1.24% / 5.11% / 1.90% / 13.80%。
- 読み込み: 面の開始で 2.6〜4.5 秒。
- 1 回目の起動は、ARK のシェルの Quit で終えたため結果が無い（異常終了ではない）。
