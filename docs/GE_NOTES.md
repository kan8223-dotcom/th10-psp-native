# GE で 3D 背景を描くときの 2 つの落とし穴

風神録の 3D 背景（4・5・6 面の床、4 面の滝など）を PSP の GE で描いたときに、実機でだけ起きた問題と、その直し方です。どちらも PPSSPP では起きないか、起き方が違うので、PPSSPP の確認だけでは見つかりません。

## 1. ガードバンドの外に出た三角形は丸ごと消える

GE は、頂点が 1 つでも画面座標 0〜4096 の範囲（ガードバンド）の外に出ると、その三角形を丸ごと捨てます。実機では、カメラの後ろ（近面より手前）にある頂点を含む三角形も捨てます。そのため、手前に大きく広がる床や滝の四角形が、画面に映っているのに消えます。

- 直し方：ワールド描画のうち、外に出る頂点を含むものだけを CPU で切ってから GE に渡す（`native/psp/GeGuardClip.hpp`、`TH10_GUARD_CLIP` と `TH10_GUARD_NEAR`）。
- 確かめ方：`--ge-debug 4` の計数で guard_draws=0 と behind_vertices=0 になること。PPSSPP の `DisableRangeCulling=True` で撮ったダンプとの差が 0 であること。
- PPSSPP はガードバンドの外の三角形を同じように捨てますが、カメラの後ろの頂点を含む三角形は描いてしまうので、後者は実機でしか分かりません。

## 2. 行列の精度で、タイルの境目に 1 ピクセルの隙間が出る

`sceGuSetMatrix` は、各 float の上位 24 ビット（仮数 15 ビット、相対誤差 3e-5）しか GE に送りません。6 面の床のように、タイルを 1 枚ずつ別の world 行列で描くと、2 枚が共有する辺の位置が描画ごとにずれます。そこに GE の 1/16 ピクセルのラスタが重なり、どちらのタイルも塗らない行が残ります。床に画面幅いっぱいの 1 ピクセルの線（奥の霧の色）が出て、床と一緒に動きます。

- 直し方：アフィンの world 行列は CPU で（float32 のまま）頂点に掛け、GE には単位行列を送る（`native/psp/GeRenderer.cpp` の `TH10_WORLD_BAKE`）。view と projection は 1 フレームの全描画で同じなので、切り詰めても描画どうしでずれません。
- 結果：PSP Go と PSP-1000 で線が消えた（2026-10-08、目視）。PPSSPP の 1〜6 面のダンプを前後で比べると、差は縁の画素だけでした（1 フレーム最大 0.13%）。ゲームの状態と速さは変わりませんでした。
- PPSSPP は GPU で float のまま描くので、この線は出ません。確認は実機でするしかありません。
